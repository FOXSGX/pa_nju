指令解码与执行

本报告记录 PA2-1 的指令实现过程、三道实验思考题及最终测试结果。

## 一 实验目的

理解程序镜像装入模拟内存后，CPU 如何从 EIP 指向的位置取出机器码、解码操作数并执行指令；掌握操作码表、ModR/M、SIB 与操作数读写接口的作用，能够根据反汇编结果定位并实现缺失指令。

## 二 实验环境与工作范围

实验在 Windows 与 WSL 环境下进行，使用 GCC 的 -std=gnu11 和 -m32 参数编译32位 NEMU，链接时同样使用 -m32。NEMU_REF_INSTR 保持关闭。主要修改指令实现及声明、instr_helper.h 中的条件宏，以及 opcode.c 中的主表、双字节表和 group 表。

## 三 关键实现过程

### 程序装载与指令解码

镜像装载地址与 EIP 初值均为0x30000。普通操作码通过主表分派，0x0F 转入双字节表，group 指令由 ModR/M 的 reg/opcode 字段进一步选择操作。modrm_rm() 等接口确定操作数位置，再通过 operand_read()、operand_write() 读取和写回。

### 使用宏复用执行逻辑

在理解单条指令的实现后，将同类指令的执行语义提取到文件内的 static 函数中，再用框架宏生成不同类型和宽度的入口。例如：

```c
make_instr_impl_2op(add, r, rm, v)
make_instr_impl_2op(add, i, rm, bv)
```

宏负责位宽、寻址、反汇编输出和长度计算，执行函数负责读取、运算与写回。bv 的8位立即数需符号扩展；cmp、test 只更新标志位；inc、dec 保持原 CF。

### 栈操作与控制转移

push 在修改 ESP 前读取源值，imm8 先符号扩展。call 保存下一条指令地址，leave 恢复栈帧，ret 取回返回地址。控制转移须补偿主循环随后增加的长度。最后补齐的 FF /4 间接跳转读取绝对目标地址，使 hello-str 成功执行到 Good Trap。

## 四 实验思考题

### 问题一 镜像装载与指令表示

使用 hexdump 查看 .img 文件时，显示的是文件偏移与各字节的十六进制数值。NEMU 的 main.c 将 LOAD_OFF 和 INIT_EIP 均设为0x30000，load_exec() 从该装载地址开始复制镜像，因此文件偏移与模拟内存地址之间满足：

```text
模拟内存地址 = 0x30000 + 文件内偏移
```

| 文件内偏移 | 对应的模拟内存地址 |
| --- | --- |
| 0x0000 | 0x30000 |
| 0x0010 | 0x30010 |
| 0x0019 | 0x30019 |

指令在机器中表现为二进制编码，hexdump 只是把这些编码按十六进制显示出来。例如，sum.img 在偏移0x19处的字节为 eb 09，对应内存0x30019处的短跳转。eb 是操作码，09 是8位有符号位移，目标地址为0x30019 + 2 + 9 = 0x30024。

一条指令可由操作码以及可选的 ModR/M、SIB、位移、立即数等字段组成，程序并不把汇编助记符作为指令存入内存。镜像还可能含常量与初始化数据，因此不能把 hexdump 中的每个字节都当成一条指令，需要结合反汇编理解。

### 问题二 执行函数中 static 的作用

instr_execute_2op() 前面的 static 使该函数具有内部链接，其名称只在当前翻译单元中可见。因此 add.c、cmp.c 等文件可以分别定义同名的执行函数，各自完成不同指令的语义。

框架的 make_instr_impl_2op() 宏在所在源文件中展开，生成的指令入口调用该文件中的 instr_execute_2op()。static 隔离的是函数符号，并不是隔离宏，也不是让不同指令共用同一个执行函数。

如果将多个源文件中这些同名函数的 static 都去掉，它们便具有外部链接，链接阶段会因多个同名定义而报错，通常提示 multiple definition of instr_execute_2op。只在某一个文件中去掉 static 不一定立即产生重复定义错误，但会使这个本应仅供文件内部使用的函数暴露到外部。

### 问题三 浮点运算与比较

test-float 使用 float 变量参与运算，并使用 == 判断结果是否等于书写的小数常量。其中的减法判断可概括为：

```c
float a = 1.2, b = 1;
float c = a - b;
if (c == 0.2) { /* 期望相等 */ }
else { HIT_BAD_TRAP; }
```

浮点数采用有限位二进制表示，1.2、0.2等十进制小数不能被精确表示为有限位二进制数。1.2 存为单精度浮点数后约为1.2000000477，减去1后约为0.2000000477，与0.2常量的表示值不完全一致。直接使用 == 比较，便可能得到不相等的结果。本次 NEMU 运行在该减法比较后于0x000300bd触发 Bad Trap，符合课程对此用例的预期。

1.2、0.2等无后缀常量在 C 中为 double，和 float 比较时涉及类型提升。加 f 后缀可统一类型，但不能消除误差；具体失败位置还受编译器与浮点求值方式影响。

编写浮点程序时，应按精度要求选择类型，避免对含舍入误差的计算结果直接判断完全相等。可按数值范围选择容差，用绝对误差或相对误差判断近似相等。本例可使用：

```c
/* 使用 fabsf 前包含 math.h；容差按具体需求选择。 */
fabsf(c - 0.2f) < 1e-6f
```

## 六 实验总结

本实验完成了指令解码、操作数访问、执行及标志位更新。宏减少了重复代码；调试时需核对位宽、符号扩展、栈段和 EIP 更新约定，并区分实现错误与浮点精度问题。
